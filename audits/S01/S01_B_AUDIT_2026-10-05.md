## Scope

S01-B closes the implementation/recovery machinery for a daily recurring monitoring schedule:

- product schedule uses `repeats=true`;
- interval start/end lifecycle is observable through generation + anchor;
- desired monitoring intent is distinct from actual DeviceActivity registration;
- launch/foreground/refresh reconcile persisted intent against system registration;
- missing/mismatched registration recovers with a new config identity;
- authorization loss fails closed while preserving desired intent;
- physically impossible early threshold callbacks fail closed;
- reboot/reopen and Stop/no-resurrection receive short target-iPhone evidence.

Natural-midnight rollover, real revoke/regrant acceptance, timezone/DST edge acceptance and all-day callback reliability are not claimed here.

The current main had advanced by one handoff-document commit after the implementation branch was created; PR #19 was mergeable and the divergence did not alter the S01-B runtime diff.

### PASS — recurring schedule and lifecycle evidence are separated correctly

The product path constructs a local daily `00:00 -> 23:59:59` schedule with `repeats=true`.

Registration presence/event count are not treated as proof that the current scheduled interval actually started. `intervalDidStart` records a local cycle key, increments interval generation once per cycle, establishes an anchor, and clears interval-local receipts. Duplicate same-cycle starts are idempotent.

`intervalDidEnd` records the callback without inventing a next interval.

### PASS — premature/stale callback paths fail closed

A threshold callback must match the current config, current registered phase, current recurring lifecycle and an active interval anchor.

Callbacks arriving physically before anchor + threshold (with an explicit 10-second tolerance) are rejected without a notification request. Unanchored callbacks, old config callbacks and old interval-generation completion callbacks are also rejected.

This is a safety lower bound only; it does not claim DeviceActivity is a perfect usage clock.

### PASS — desired intent and actual registration are reconciled

The main App separately persists desired monitoring intent and reads actual DeviceActivity registration/event count/schedule state.

- desired OFF never auto-recovers and removes stray owned registrations;
- desired ON + exact registration keeps the current config;
- missing/mismatched registration creates a new UUID-backed config;
- failed recovery is held rather than repeatedly retried on refresh;
- authorization loss stops system registration, preserves desired intent and records a blocked lifecycle;
- later reapproval is routed through a new-config recovery path.

The target-iPhone reboot observation supports the same-registration persistence path.

### PASS — privacy/product boundary unchanged

The shared diagnostic state contains app-owned config/lifecycle/counters only. No selected App identities, bundle IDs, protected Today report data or exact sessions are added to App Group state.

No Shield/ManagedSettings/blocking path is introduced.
