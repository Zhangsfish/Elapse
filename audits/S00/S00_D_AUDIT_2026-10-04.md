### PASS — current user / current device scope matches Apple API

Apple's current DeviceActivity documentation states:
- `DeviceActivityFilter.users == nil` includes only the current user;
- `DeviceActivityFilter.devices == nil` includes only the current device;
- `DeviceActivityData` is activity data for a person on a specific device.

The host uses the current-user initializer path, explicitly passes `devices: nil`, and filters by selected opaque application tokens.

The report extension additionally fails closed unless exactly one iPhone device record is returned. This is conservative rather than silently aggregating unexpected scope.

Owner device evidence shows the expected current-user/current-iPhone report rendered normally.

### PASS — Today means local start-of-day through now

`TodayInterval.make(now:calendar:)` now returns `calendar.startOfDay(for: now) → now`.

Tests cover ordinary day, spring-forward DST and fall-back DST. The implementation does not assume every calendar day is exactly 24 hours.

### PASS — selected-App aggregation uses the correct source

Apple documents `ApplicationActivity.totalActivityDuration` as the activity time for that application.

Apple separately documents `ActivitySegment.totalActivityDuration` as the time the device screen remained on during that segment.

The report sums filtered `ApplicationActivity.totalActivityDuration` per opaque application token and per hourly segment. It does not use segment screen-on duration as selected-App usage.

Pure arithmetic tests verify repeated-app and repeated-hour accumulation plus total = sum of per-App durations.

### PASS — protected report data remains inside ReportExtension

Protected `DeviceActivityData` is read and aggregated inside the DeviceActivityReport extension.

The main App provides selection/filter/host only.

The S00-B/C App Group remains app-owned experiment/diagnostic state. PR #17 does not add report totals, hourly usage, App labels, tokens or report output to that shared container.

The shared aggregation helper is pure arithmetic and does not persist/export usage.

### PASS — normal, zero and unavailable are distinct

The report distinguishes:
- `content`: one current-iPhone report record and positive selected-App duration;
- `zeroUsage`: one current-iPhone report record with no positive selected-App duration;
- `unavailable`: absent/unexpected device scope or unattributed positive activity.

The UI renders different copy for zero usage and unavailable data. It does not treat an empty/unavailable report as authoritative zero.

Zero/unavailable were not deliberately induced on-device; accepted evidence is SOURCE + UNIT_TEST.

### PASS — system-managed loading is described honestly

The host does not fabricate a report completion callback. It tells the user iOS loads the Screen Time report and may take a moment.

S00-D records this as `SYSTEM_MANAGED_LOADING`; no App Group handshake or fake loading-complete state was added.
