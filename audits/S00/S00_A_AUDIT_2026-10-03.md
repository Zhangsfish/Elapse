## Findings

### PASS — final signed distribution artifact closes the 19.1 entitlement gap

For Everwhile 0.1.0 (27.1), run 37120646140 exported one IPA, computed SHA-256 `b25278ad76f32be1a120aa578630dcb417c85d084fd1d9b5cd9868f66cf3f501`, and audited that exact IPA before upload.

For the main App, Monitor extension, and Report extension, the job recorded:

- expected bundle ID;
- `codesign --verify --strict` VALID;
- `com.apple.developer.family-controls=true` in the code-signature claim;
- `com.apple.developer.family-controls=true` in the embedded profile allowance.

The script then uploaded the same audited IPA path. App Store Connect reached `VALID` and `INTERNAL_ONLY`. Run 37121122810 later recorded `IN_BETA_TESTING`, an internal group, and assignment of build 27.1 to that group.

This distinction matches Apple TN3125: a provisioning-profile entitlement is an allowlist and is not itself proof that the app claims the entitlement in its code signature. Apple also requires Family Controls distribution permission/configuration for the app and relevant Screen Time API extensions.

### PASS — reviewed head does not invalidate the installed runtime evidence

The uploaded commit `88697237...` and implementation/test SHA `d1b2a764...` differ only by read-only App Store Connect availability-check workflow/scripts. No App runtime source changed.

From `d1b2a764...` to reviewed head `bf5530e...`, only STATUS/docs/reports changed. Therefore the App runtime exercised on the owner's 27.1 device is the same App runtime contained in the reviewed PR head.
