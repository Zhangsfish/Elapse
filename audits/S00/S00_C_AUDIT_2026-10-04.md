### PASS — six independent threshold diagnostics

The shared snapshot now stores a `PulseThresholdDiagnostic` per threshold.

Each threshold independently records:

- callback arrival;
- callback time;
- request status;
- request completion time;
- safe error code.

Receipt identity remains experiment + threshold event, so one threshold cannot suppress another.

The main App renders and copies diagnostics for 5/10/15/20/25/30 separately.

### PASS — migration from S00-B shared state is explicit and fail-closed

The 32.1 shared snapshot's legacy five-minute fields are decoded into the new threshold map.

Active state without an experiment identity throws rather than guessing.

Malformed or incomplete active state fails closed through the shared store read path.

Tests cover legacy migration, round-trip encoding, persistent storage and corrupt/incomplete input.

### PASS — duplicate, stale, invalid and late-completion semantics

Tests verify:

- first callback for each threshold may request once;
- duplicate callback for the same threshold is rejected;
- receipts are independent across thresholds;
- stopped/failed/old-experiment callbacks are stale;
- invalid event names do not request a pulse;
- a late completion from an old experiment cannot mutate the current experiment;
- a repeated completion cannot overwrite an already accepted request;
- request failure remains visible on only its threshold and does not create a second uncertain pulse.

No stale/duplicate/late completion naturally occurred during the device run. Those claims are SOURCE + UNIT_TEST evidence, not DEVICE_OBSERVED.

### PASS — out-of-order arrival is recorded, not rewritten into fake precision

The state machine accepts valid current-experiment threshold callbacks by event identity and stores the actual callback timestamp for each threshold.

It does not infer missing thresholds, reorder timestamps, or derive authoritative usage from callback spacing.

Unit tests cover out-of-order 20-minute then 10-minute arrival with independent timestamps.
