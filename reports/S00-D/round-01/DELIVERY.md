Source: The app host passes selected opaque application tokens to an hourly DeviceActivity filter. The current-user initializer and explicit `devices: nil` scope to current user/current device. `TodayInterval` uses the supplied local calendar's start of day through now, including DST days. The report extension alone reads protected `DeviceActivityData`, rejects absent/multiple/non-iPhone records as unavailable, sums filtered `ApplicationActivity.totalActivityDuration` per token and hour, and renders Apple's opaque App labels. The app does not receive report durations, identities or buckets through App Group. Normal, selected-App zero, and unavailable content differ; host loading is `SYSTEM_MANAGED_LOADING` because there is no reliable completion hook.

API basis: Apple [filter initializer](https://developer.apple.com/documentation/deviceactivity/deviceactivityfilter/init%28segment%3Adevices%3Aapplications%3Acategories%3Awebdomains%3A%29), [devices nil](https://developer.apple.com/documentation/deviceactivity/deviceactivityfilter/devices-swift.property), [report scene](https://developer.apple.com/documentation/deviceactivity/deviceactivityreportscene/makeconfiguration%28representing%3A%29), [application duration](https://developer.apple.com/documentation/deviceactivity/deviceactivitydata/applicationactivity/totalactivityduration), [segment screen-on duration](https://developer.apple.com/documentation/deviceactivity/deviceactivitydata/activitysegment/totalactivityduration). `DeviceActivityData.lastUpdatedDate` is displayed as the system report update time, not an exact completion timestamp. These are SDK/source facts, not device evidence.
